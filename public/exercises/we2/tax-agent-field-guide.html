First: what is an "agent"?

A chatbot answers one question and stops. An agent keeps going on its own: it looks at the situation, thinks about what to do, does it, looks again. The language model is the brain. The tools you give it are its eyes and hands. Your job in this notebook is to build the loop that connects them.

What happens in "Clone Repository & Install Dependencies"?

"Clone" is the GitHub word for "download a copy". The cell fetches the whole course project into a folder in your Colab session and then installs the few extra Python packages the notebook needs. While the course repository is still private, the cell also needs a GitHub access token; your TA has one. Once the material is public, the cell simply downloads without asking.

What happens in "Build & Serve the React Frontend"?

The practice tax form is written as a web app. Build turns its source files into the plain HTML, CSS and JavaScript a browser understands. Serve starts a tiny web server inside your Colab session that hands out those files. From then on the notebook can show the form to you (Section 2) and, later, to the agent (Section 8). The cell prints the address it is served at; every later cell reuses it.

Can I use a different model?

Yes. OpenRouter offers hundreds of models under one key. Pick one from the list at openrouter.ai/models and put its name (in the form vendor/model) in the model line at the top of the setup cell. Names ending in :free cost nothing but are slowed down, which shows up as long waits in the full run.

Keep in mind that the same model also acts as the "judge" for free-text answers when you score your run in Section 9, so the model you pick grades part of your own work.

The test printed a paragraph about "refining core logic" instead of "Hallo".

Some models think before they answer, and that thinking uses part of the reply budget. If the budget is very small, the model runs out of room before it gets to the actual answer, and what you see is a leftover of its thinking. The current notebook gives the test enough room; if you still see this, simply run the cell again or pick another model.

Most boxes are copied straight from a document. A few, like this flat-rate deduction for professional expenses, are computed: the AI needs both a document and a guide, and must actually do the arithmetic.

Why doesn't the AI simply read all the documents every time?

Because more text is not better. The hardest taxpayer has eleven documents; sending all of them for every one of the 28 pages would bury the two or three relevant numbers in pages of irrelevant lines, and language models get measurably worse at picking the right number out of a long, noisy text. Instead, the AI first looks at the labels on the folder (name and one-line description) and asks for only what it needs, the same way you would pull one file from a cabinet rather than dump the whole drawer on your desk.

It also makes the agent easier to understand: for every page you can later see exactly which documents it asked for, and spot a wrong answer that came from never opening the right file.

What to take away from Section 3
Two kinds of material: documents hold the facts about the taxpayer, guides hold the rules. The AI sees only labels until it asks to open something; then it gets the full text. Copying a value needs a document; computing a deduction needs a document and a guide. The Deductions pages need both, every time.

Notebook section 4 · 🧰 Tools

Nine tools: how the AI sees, reads, acts and asks.

A language model on its own can only produce text. To fill a form it needs a way to look at the page, open documents, type values and press buttons. Those abilities are given to it as tools: named actions it can request, which the notebook then carries out for it. This section lists the nine tools and shows what one of them returns.

READ · NO TASKS

Everything the AI learns arrives through these nine tools, and everything it does goes out through them. It has no other way to perceive the form or the documents.

Behind the scenes each box has a unique technical name, like a house number, so "type 142 000 here" is unambiguous. The AI must use the names it was shown on the page; it is not allowed to invent one.

Who actually presses the keys?

The AI proposes. The notebook acts.

In this project the language model never touches the form directly. It answers in text: "put 142 000 into the gross-salary box". Your Python code reads that answer and calls the typing tool. The same goes for opening documents: the AI names the file, the code fetches it. This keeps every action visible in your own code, and it is why the notebook's ✅ checkpoints can test your work without prompting the model at all.

The notebook calls this an "MCP server". What is that?

Think of a waiter. The AI sits at the table and can only say things: "bring me the salary certificate", "write 142 000 into the gross-salary box", "press Next". The waiter goes and does it, then comes back and reports what happened. The server is that waiter: one program that owns the nine tools and carries them out on the form and the file folder. MCP (Model Context Protocol) is simply a widely used standard for how an AI and such a waiter talk to each other, so the same tools could be offered to any model or app. In this notebook you use the tools through plain Python calls; the standard matters more if you want to plug the same tax tools into another AI product later.

What to take away from Section 4
The AI has no screen, no keyboard and no file browser of its own. These nine tools are how it is fed information (what is on the page, what a document says, what the taxpayer answers) and how it acts (type, click, hand in). Whatever a tool does not tell it, the AI does not know; whatever it cannot request through a tool, it cannot do. Designing an agent is largely deciding which tools to give it and when.

Why this step matters so much

Whatever the plan leaves out, the AI never sees.

In the next section the AI writes plans like yours for every page, and then fills the page using only the documents and guides its own plan asked for. Nothing else is shown to it. So a plan that forgets the bank statement means an empty interest box, and a Deductions plan that forgets the rule book means a guessed or missing deduction. Is the plan already the answer?
No. The plan for the Deductions page says "read the net salary and apply the flat-rate rule from the guide". The number 3 765 only appears later, when the AI has the certificate and the guide open in front of it. A good plan can be checked before any document is opened: does every box have a named source, and does every computed box have a named rule?
What to take away from Section 5
Planning means deciding what to read and how to use it, without seeing the contents. By writing one plan yourself you now know what a good one looks like, which is exactly what you need to judge the AI's plans in Section 7 and to debug wrong answers in Section 9: most of them trace back to a plan that opened the wrong file or forgot the rule book.

The test at the end · Task 5

Four numbers tell you whether the whole page works.

For Anna the Income page has four boxes with known answers: gross salary 142 000, social-insurance 7 526.60, pension fund 8 400, interest 12.50. The notebook prints your AI's values next to them with a ✓ or ✗. All four ✓ means plan, reading and filling all worked on this page.

Why prompt the model twice instead of once?
  • You can test each half. The checkpoints inspect the packets you build. One giant prompt could only be tested by running it.
  • Less noise. The second prompt carries two or three relevant documents instead of all eleven, on every one of 28 pages.
  • You can see what happened. Every plan is saved and drawn in Section 7. When a value is wrong you can see whether the right file was ever opened.
The Task 5 table shows a ✗. Where do I look, in what order?
  1. The plan. Print plan["documents_needed"]. Is the salary certificate in it, spelled exactly like the catalog?
  2. The reading. Print doc_contents.keys(). Did the loop actually open it? If the list you handed it in Task 4a was the wrong one — or an empty one — the second prompt carries no documents at all.
  3. The packet. Print the message Task 3 built. Does it contain 142,000.00? If not, the document text is not making it into the packet.
  4. The AI's reasoning. Look at mapping["_thought"]. A model that added the accident-insurance line to the social-insurance total ignored the section rules: check that Task 4b appends them.
  5. The box names. Every key in mapping must be a box that was on the page. Invented names fail later when the value is typed in.
What to take away from Section 6
One page, three moves: the AI decides what to read, your code reads it, the AI turns it into values. The system prompt sets the job; the packet you build is the only thing the AI knows about this particular page. When something goes wrong later, it is almost always one of these three moves, and you now know how to check each one.

Notebook section 9 · 📊 Score

Every box is compared with the answer key, and every verdict says why.

The scorer takes the return your agent handed in and compares it, box by box, with a hidden answer key for that taxpayer. Each box is compared in the way that suits its kind (a number, a date, a name…). The score card shows the total, lists what was wrong or missing, and tells you for each which rule decided it.

score = (correct − ½ × extra) ÷ total × 100 total: boxes the answer key fills in. missing: the key has a value, you left it empty. extra: you filled a box the key leaves empty; each costs half a point. Leaving a box empty where the key says 0 is fine.
Trace a wrong or missing box backwards

Start from the "Decided by" column.

1Missing · Open that page's plan card. Was the right document ticked? Then look at the "Filled / FAILED" lines: was the box on the page, and did typing into it succeed?
2Wrong amount · A fact was misread or a rule misapplied: the accident-insurance line added to social insurance, a flat rate not capped, spouses not summed. Read the AI's own reasoning for that page.
3Wrong text · Usually the wrong thing entirely, such as the employer's address instead of its name.
4Extra · You filled a box the key leaves empty. Typical: a 0 written into a deduction the taxpayer does not have, or an extra row in a table.
Rules that are easy to miss
Table rows are matched by name, not by position.

Bank accounts by bank name, children by name, debts by creditor. A row the key has and you do not costs one point per box in it; a row you add that the key does not have counts as extra, per box.

Writing 0 is not the same as leaving a box empty.

A 0 in a deduction the taxpayer does not have is an extra. The AI is told not to do this; if it does, tighten the rules for that section.

The AI judge only ever looks at free text.

Amounts, dates, choices and identifiers are compared by fixed rules. Only names and descriptions can go to the judge, and its verdicts are remembered so re-scoring is free.

Glossary
  • Taxpayer (persona): one simulated person or couple, with a folder of documents, a script for answering questions, and a hidden answer key.
  • Plan: the AI's decision, for one page, about which documents and guides to open and how to use them.
  • Packet (user message): everything about the current page that your code sends to the AI in one call.
  • System prompt: the fixed job description the AI gets with every prompt.
  • Section rules: extra instructions added to the job description for one section of the form (Income, Deductions, Wealth…).
  • Memory (filled history): everything successfully typed on earlier pages, shown to the AI again on later pages.
  • Decided by: the comparison rule that settled a box's verdict on the score card.
What to take away from Section 9
The score is a diagnosis of the whole pipeline. Because every verdict names the rule behind it, you can tell a reading failure (missing) from a reasoning failure (wrong amount) from over-eagerness (extra), and fix the earliest step that broke: plan, reading, filling, or navigation.

What to try once Anna scores well.

Each of these is a contained change to something you already built, and each can be measured with the Section 9 score card.

  • Send less. The bank statement currently reaches the AI twice, once as plain text and once as a table. Send only one form and check the score holds.
  • Check the typing. After filling a page, look at the page again and compare what is in the boxes with what you sent. Redo the boxes that did not stick.
  • Let it ask. When the plan says a question to the taxpayer is needed, actually ask, and add the answer to the packet. Yuki's blurry day-care receipt is the test case.
  • Compare models. Switch the model, re-run the same taxpayer, compare score, time and cost. Keep the scorer's judge model fixed so the grading does not move.
  • Ask for confidence. Have the planner rate its confidence per box and skip or flag the doubtful ones; see whether extras drop faster than correct answers.
